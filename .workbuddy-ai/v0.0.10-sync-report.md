## 1. 背景：为什么不能直接 merge

| 项 | 情况 |
|---|---|
| 本地 origin | `tianjiangqiji/upstream-ops` |
| 上游 | `bejix/upstream-ops` |
| 历史关系 | **完全无关**（无共同祖先）——本地原是把上游快照压成的单个 `first commit` |
| 本地内容基线 | 等价于上游 `a4d83c7`（= v0.0.9 + PR #22），与它仅差 10 个文件 |

直接 `git merge v0.0.10` 会因空合并基底产生几十个伪冲突。因此采用**嫁接上游历史**方案。

## 2. 执行步骤

1. `git remote add upstream https://github.com/bejix/upstream-ops.git`，fetch 到 v0.0.1～v0.0.10
2. 备份：分支 `backup/pre-v0.0.10` + 标签 `pre-v0.0.10`（指向旧 `9b6db42`）
3. 用 `git commit-tree <main 的 tree> -p a4d83c7` 造出「下游定制」提交 `0b6a3ab`，
   把本地内容挂到上游历史上（内容与旧 main **逐字节一致**，已验证 `git diff` 为空）
4. `git merge v0.0.10` → 26 个文件，仅 **2 处冲突**
5. 解决冲突 → `go build` / `go test` / `tsc` / `vite build` 全部通过
6. `main` 指向合并提交；删除临时分支 `sync/v0.0.10`

**结果**：`git fetch upstream --tags && git merge upstream/main` 即可完成后续同步。

## 3. 冲突解决（2 处）

### `backend/global/version.go`
保留下游版本线：`0.1.0` → **`0.1.1`**（上游为 `0.0.10`）。

### `frontend/components/monitor/channel-cards.tsx`
3 段冲突。本地与上游**各自独立实现了同一个「每页数量持久化」功能**：

| | 本地实现 | 上游实现 |
|---|---|---|
| storage key | `upstream-ops:channel-page-size` | `monitor-channel-page-size-v1` |
| 读取 | 无 try/catch | `try/catch` + 脏值回退 |
| 写入 | 直接 `setItem` | `saveChannelPageSize()` 封装 + `try/catch` |

**采用上游实现**（功能等价、更健壮）。副作用：老用户已存的每页设置会因 key 变更回落到默认值一次。

> 注：本地另一处定制「阈值/状态条件渲染」不在此冲突中，已自动合并保留（见第 5 节）。
