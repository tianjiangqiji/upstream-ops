（只有一个压缩提交 `first commit`）。内容上等价于上游 `a4d83c7`（= v0.0.9 + PR #22），
与它只差 10 个文件。

**方案（用户选定：嫁接上游历史）**：
- 加 `upstream` remote，fetch 到 v0.0.1～v0.0.10
- 备份 `backup/pre-v0.0.10` 分支 + `pre-v0.0.10` 标签
- `git commit-tree <main tree> -p a4d83c7` 造「下游定制」提交 `0b6a3ab`，
  把本地内容挂到上游历史上（tree 与旧 main 逐字节一致）
- `git merge v0.0.10` → 26 个文件，仅 2 处冲突 → 合并提交 `eaf943e`
- main 已指向合并结果；**未 push**（用户选择先本地确认）

**冲突处理**：
- `backend/global/version.go`：保留下游版本线，0.1.0 → **0.1.1**
- `frontend/components/monitor/channel-cards.tsx`：本地与上游各自实现了
  「每页数量持久化」，采用上游版（含 try/catch 与脏值回退，更健壮）

**校验**：`go build ./...` 通过；`go test ./...` 全绿；`tsc --noEmit` 通过；
`vite build` 通过。工作区干净。

**踩坑（重要）**：
- 冲突文件是 **CRLF**，用 Edit 工具直接改会匹配失败。改用 Python 按 `\n` 归一化处理、
  写回时再转回 CRLF。
- 解决 `version.go` 时只替换了版本字符串、**漏删冲突标记**，导致 `go build` 报
  "syntax error: non-declaration statement outside function body"。
  之后补了「全仓冲突标记复查」步骤（`git grep -E "^(<<<<<<< |>>>>>>> |=======$)"`）。
- `npm ci` 在 esbuild postinstall 会因 Windows 文件占用 **EBUSY** 失败；
  且沙箱会拦截 `npm ci` 对 `node_modules/.bin` 的批量删除。
  改用 **`npm install --ignore-scripts`** 补齐缺失依赖即可
  （`@esbuild/win32-x64` 自带 `esbuild.exe`）。
- `npm install` 会顺手改动 `frontend/package-lock.json`（npm 版本差异导致的 `libc` 字段
  增删），与合并无关，已 `git checkout --` 还原。

**待办**：README 仍指向上游镜像 `ghcr.io/bejix/upstream-ops` 与 `IMAGE_TAG=v0.0.10`，
